<objective>
Wire the four already-registered milestone tools (`write_wellness_entry`,
`enrich_activity_climbing`, `create_climbing_activity`,
`complete_climbing_session`) into `server.py` as **explicit named imports**
and `__all__` entries, and refresh the module docstring's "MCP tools
provided" list to enumerate the full milestone surface.

Purpose: Today the wellness and climbing import lines each name a single
tool. Anything else those modules expose registers via the
`@mcp.tool()` decorator side-effect on import — meaning if a future
refactor deletes the `from .tools.X import Y` line, the tool quietly
disappears from `tools/list` with no test or import error to flag it.
D-01 closes that hole by making the wiring loud: every tool the milestone
ships is named at the import site and re-exported via `__all__`, mirroring
the established activities/events/custom_items pattern in the same file.
D-02 keeps the docstring's tool list truthful for the milestone surface.

Output: A single modified file (`src/intervals_mcp_server/server.py`)
with ~6 lines net added. No tool modules touched. No new behavior. No new
HTTP. The change is additive — every existing import and `__all__` entry
stays in place.
</objective>
